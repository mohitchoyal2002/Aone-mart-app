# Aone Mart — native Android app + backend

One React Native Android app has separate Customer and Admin workspaces. Admin uses a sidebar on Android tablets and compact navigation on phones. The customer app has Home, Cart, My Orders and Profile tabs. UI uses native React Native components, NativeWind/Tailwind, DM Sans, forest green and warm neutral colours.

## What is included

| Area | Implemented behaviour |
| --- | --- |
| Customer auth | Name, Indian phone number and password signup; customer login; profile/password updates |
| Admin auth | Separate admin login; admin/customer roles enforced by the API |
| Shopping | Product images or bundled illustrations, search, categories, quick add, persistent cart |
| Checkout | Server-calculated prices, coupons, reward points, price-change review and idempotent order retries |
| Pickup orders | Place → admin accepts/rejects → admin marks packed → customer confirms collection |
| Inventory | Add/edit/hide products, categories, available/reserved stock, low-stock indicators and graphs |
| Accounts | Create/edit customer or admin accounts, reset passwords, adjust points with a reason, soft delete and restore |
| Imports | Product CSV; invoice CSV; PDF/JPEG/PNG invoice drafts extracted through Gemini |
| Reports | Date-filtered sales, revenue, estimated gross profit, daily/category graphs, top products and CSV export |
| Rewards | Points ledger; percentage/fixed coupons; customer-targeted coupons; dates, caps and usage limits |
| AI Summary | Read-only Gemini chat about current inventory, selected sales range, customers and coupons; Hindi/English questions |

## 1. Start the backend

Install **Node.js 24 or newer**. The backend uses Node's built-in SQLite module. Extract this package, open a terminal in `aone-mart`, then run:

```bash
npm ci
npm run setup
```

Setup creates a private `apps/api/.env` with a random JWT secret and an initial admin password. It prints the generated password once. Existing configuration is preserved.

Edit `apps/api/.env`:

```dotenv
ADMIN_NAME=Aone Mart Admin
ADMIN_PHONE=your_10_digit_mobile_number
ADMIN_PASSWORD=your_unique_password_at_least_12_characters
GEMINI_API_KEY=your_private_gemini_key
```

Keep `JWT_SECRET` generated by setup. Do not put the Gemini key in a mobile file or any `EXPO_PUBLIC_` variable. Credentials and the local test database are excluded from the source package.

Create the first admin, optionally load sample inventory, and start the API:

```bash
npm run bootstrap-admin -w @aone/api
# Optional: sample products only, no sample sales or customer accounts.
npm run seed
npm run api
```

The API listens on port 4000. Check it using:

```bash
curl http://localhost:4000/health
```

The admin uses the phone/password you configured. Public signup always creates a customer. Admin can create further administrators in the Customers screen. Bootstrap preserves existing accounts; it does not reset a password when run again.

## 2. Run the Android app locally

Install Android Studio with its SDK, Android platform 36, a compatible JDK and the build tools requested by Gradle. An Android emulator or physical Android device is needed.

Copy `apps/mobile/.env.example` to `apps/mobile/.env` and set:

```dotenv
# Android Studio emulator:
EXPO_PUBLIC_API_URL=http://10.0.2.2:4000
APP_VARIANT=preview
```

For a physical phone, use your computer's LAN IP, for example `http://192.168.1.20:4000`. Both devices must be on the same network and the backend port must be reachable. `localhost` on a phone means the phone itself.

From the project root:

```bash
npm run android
```

The app also has a native first-launch server connection screen if no URL is baked into the build. It checks `/health` before saving a server URL. Production builds require HTTPS; preview builds permit local HTTP.

Use a compiled Android build to test custom sounds and remote push. Expo Go is not the delivery target.

## 3. Build an installable APK with EAS

An EAS `preview` profile is included and outputs an APK. `production` outputs an AAB for Google Play.

If this extracted folder is not already in a Git repository, run `git init` from `aone-mart` first so EAS can identify the complete workspace. No remote repository is required.

```bash
cd apps/mobile
npx eas-cli@latest login
npx eas-cli@latest init
```

Link this app to your Expo project. Since `app.config.ts` is dynamic, if the CLI cannot write the project ID automatically, copy the resulting project UUID into `EXPO_PUBLIC_EAS_PROJECT_ID` in the mobile environment file. The config reads it into `extra.eas.projectId`.

Set your publicly reachable HTTPS API URL and Expo project ID in the EAS environment used by the build, or directly in the chosen profile's `env` in `eas.json`. These two values are public configuration, not secrets. EAS must receive them; an ignored local `.env` file by itself is not a reliable cloud-build configuration.

```bash
npx eas-cli@latest build --platform android --profile preview
```

Alternatively, the repository’s **Android APK** GitHub Actions workflow compiles a self-contained APK with notifications disabled, without an Expo account. Its CI output uses a build signing key and must be re-signed with the retained private release key for distributed updates. Download the APK from the resulting build page and install it on Android. The backend must remain reachable for shopping, orders and reports. The application JavaScript is bundled into the preview APK, so Metro is not required to run that APK.

For Google Play:

```bash
npx eas-cli@latest build --platform android --profile production
```

Native `android/` and `ios/` folders are deliberately excluded from the source archive. Expo generates native code from the app config and plugins during build. When changing native configuration locally, regenerate with:

```bash
npx expo prebuild --platform android --clean
```

The custom tone is `assets/aone_order.wav`. The notifications plugin copies it into Android resources. Production prebuild disables cleartext network traffic.

Official references: [APK builds](https://docs.expo.dev/build-reference/apk/), [EAS monorepos](https://docs.expo.dev/build-reference/build-with-monorepos/), [EAS environment variables](https://docs.expo.dev/eas/environment-variables/).

## 4. Enable background order alerts

Foreground authenticated WebSocket notifications are implemented. To receive alerts while the admin app is in the background:

1. Create/link your Expo project and set `EXPO_PUBLIC_EAS_PROJECT_ID` for the Android build.
2. Register an Android app in Firebase using package `com.aonemart.app`.
3. Place its Android `google-services.json` in `apps/mobile/`. The config uses it when present.
4. Configure the Firebase FCM V1 service-account credential with `npx eas-cli@latest credentials --platform android`.
5. Set `ENABLE_NOTIFICATIONS=true` in both mobile build and backend runtime configuration, rebuild the APK with the same release signing key, sign in on a physical Android device and allow notifications. Admin → Store Settings has notification enable/status and a tone test.
6. Place an order from a second customer's device. Verify foreground and background alerts, tone, accept/reject and packed updates.

The Firebase service-account private key belongs in EAS credentials, not in the app or source repository. If enhanced Expo push security is enabled, put its access token in the backend's `EXPO_ACCESS_TOKEN`.

New orders use Android channel `aone-orders-v1` and `aone_order.wav`; customer updates use `aone-updates`. Android notification settings can mute a channel. Sound changes require a new channel identifier and native rebuild. Android force-stop prevents background delivery until the app is reopened.

Remote push includes a generic message to limit details on a lock screen. The signed-in app fetches order details. The backend queues notifications, retries provider failures and checks push receipts; the notification inbox remains available even if delivery fails.

Official references: [Push setup](https://docs.expo.dev/push-notifications/push-notifications-setup/), [FCM V1 credentials](https://docs.expo.dev/push-notifications/fcm-credentials/).

## Store workflow and rewards

Orders reserve stock at placement. Accepting an order preserves the reservation. Packing notifies the customer to collect it. The customer confirms "I've picked up my order" after collection/payment. Pickup consumes stock, creates the sales invoice and awards points exactly once.

Rejection requires a reason. Customers can cancel while an order is still placed. Rejection/cancellation releases reserved stock, refunds spent points and releases the coupon reservation. Stock cannot be reduced below existing reservations.

Payment is **at the mart**. No payment gateway or delivery workflow is included. Pickup confirmation is customer-driven as requested; it does not verify a payment gateway transaction. A pickup reference code is displayed for the mart, while the API also supports an administrator completing a packed order.

Default earning is **1 point per full ₹100 of the final order total**. One redeemed point saves ₹1. Change earning rate in Store Settings. A coupon is applied first, then eligible points. Pending orders reserve coupon usage to prevent exceeding its limits. Imported historical invoices do not award points again.

Soft deletion disables login and revokes sessions while keeping invoices and order history. Admin cannot disable a customer with an active order, or disable/demote their own account. Disabled accounts can be restored; their old credentials' sessions stay revoked.

## CSV and invoice imports

Use Admin → Manage Inventory → Import CSV. The preview validates the file before any database changes. Review the summary and first 20 rows, then confirm. Any invalid row blocks the whole import; commits run in one transaction. Limits: 5 MB/file and 5,000 rows. Duplicate import files and existing invoice numbers are protected against replay. Preview expires after 24 hours.

### Products

Template: `samples/products.csv`. All price fields are **rupees** in CSV/forms; API response amounts are **integer paise**.

| Field | Meaning |
| --- | --- |
| `sku`, `name`, `category` | Required; SKU identifies an existing product for updates |
| `price`, `mrp`, `stock` | Required; MRP ≥ price; stock is total on-hand quantity, not a quantity to add |
| `cost` | Purchase cost/unit; defaults to 0 |
| `low_stock_threshold` | Defaults to 5 |
| `unit` | Defaults to `1 unit` |
| `image_url` | Optional HTTPS image URL; otherwise a bundled illustration is shown |
| `artwork` | `rice`, `milk`, `oil`, `fruit`, `vegetable`, `soap`, `bread`, `bag`, `snack` or `tea` |

Existing active SKUs are updated; missing categories are created. A hidden SKU must be restored through an appropriate inventory update before it can be imported. CSV import stock cannot be below reserved quantity.

### Sales invoices

Template: `samples/sales-invoices.csv`. Import inventory first so every SKU exists.

Required columns: `invoice_number,invoice_date,sku,quantity,unit_price`. Optional: `customer_phone,discount`.

Use `YYYY-MM-DD` dates. Price and discount are rupees; discount is the **total line discount**, not a per-unit amount. Multiple rows with the same invoice number form one invoice and must agree on date/customer. A blank customer phone is permitted. A supplied phone links to a matching customer account if one exists; otherwise it is retained on the imported invoice without creating a customer account.

Historical imports do not change stock by default. Enable "Deduct inventory" only for sales not already reflected in your stock counts. If any line cannot be deducted without violating reservations, the complete import rolls back. These are operational sales records, not a full accounting/tax invoicing system.

For PDF/JPEG/PNG invoice import, Gemini extracts a draft. Printed SKU and date must be identifiable. Review the extracted rows before confirming. Missing/incorrect fields require a corrected CSV; AI output is never imported automatically. Sample invoices are illustrative and should only be imported into a test database.

## Reports and AI

Reports use **Asia/Kolkata** date boundaries, with selectable 7/30/90-day or custom ranges up to 366 days. Revenue is invoice net total; category/top-product values are gross line sales. Estimated gross profit is net revenue minus recorded product cost, excluding other expenses. Pending, rejected and cancelled orders do not become sales invoices.

Gemini requests run only on the backend. Admin can ask, for example, "Kaunse products ka stock kam hai?" or "Selected dates ki sales aur top products batao". The chat includes the selected sales range and current database context. Responses are read-only; no stock, accounts, coupons or orders can be modified by AI.

Context includes aggregate reports plus up to 200 inventory products, 50 recent customers and 200 coupons. It excludes passwords, API keys and customer phone numbers. Lists are bounded, so the model must disclose incomplete coverage. Inventory/customer names and imported documents are treated as untrusted data. AI answers and invoice extraction may fail when the configured model, key or quota is unavailable; the app shows an error and leaves data unchanged.

## Deploy the API

For a Node server:

```bash
npm ci
npm run setup
# Configure apps/api/.env before the commands below.
npm run bootstrap-admin -w @aone/api
npm run build:api
# Set NODE_ENV=production in backend configuration.
npm run start -w @aone/api
```

Keep SQLite on persistent storage. Use one API process/instance so its WebSocket clients, push worker and SQLite transactions remain coordinated. Place an HTTPS reverse proxy in front of port 4000 and pass WebSocket upgrades for `/realtime`. Set `TRUST_PROXY=1` only when there is exactly one trusted reverse proxy. CORS origins are optional for authorised development tools; the Android app does not require browser CORS.

`deploy/vps/compose.yaml` supplies a persistent API and Caddy HTTPS proxy for a VPS. Read [the deployment guide](docs/deploy-backend.md). The Docker startup script bootstraps the configured admin before serving traffic and retains existing passwords on restarts. A Dockerfile is included; Docker itself was not available for verification here:

```bash
docker build -f apps/api/Dockerfile -t aone-mart-api .
docker volume create aone-mart-data
docker run --rm --env-file apps/api/.env -e NODE_ENV=production -e DATABASE_PATH=/data/aone.sqlite -v aone-mart-data:/data aone-mart-api node dist/bootstrap.js
docker run -d --name aone-mart-api --env-file apps/api/.env -e NODE_ENV=production -e DATABASE_PATH=/data/aone.sqlite -p 4000:4000 -v aone-mart-data:/data --restart unless-stopped aone-mart-api
```

Use consistent SQLite backups and test a restore. For a simple stopped-server backup, stop the API cleanly, copy the database, then restart. Do not deploy with sample inventory or fabricated store information. Set a new restricted server-side Gemini key for the production environment.
